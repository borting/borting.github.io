這篇是為了替 [git-repo](https://gerrit.googlesource.com/git-repo/) 的 sync 加入 worktree 方所做的 feasibility study.
目的是了解幾個 `git clone` 選項的異同, 以及與 `git worktree` 的差異

# Clone Options

不管使用哪種 git clone 方式產生的 repository, 都是一個獨立運作的 repository (有獨立的 git config).
差別在於 clone 時, objects 的來源 (remote/local), 以及 object store 是否共用.
git worktree 則不同, 其產生的 working directory 和原始的 working directory 共用同一個 git directory, 所以也共用了同樣的 git config 和 object store.

Command               | Clone Source | Copy on Clone | Object Store      | Remote Tracking
------------------------------------------------------------------------------------------
git clone             | local/remote | Yes           | standalone        | clone source
git clone --local     | local        | Yes/No        | standalone        | local
git clone --shared    | local        | No            | shared            | local
git clone --reference | local+remote | Partial       | shared+standalone | remote
git clone --bare      | local/remote | Yes           | standalone        | clone source
git clone --mirror    | local/remote | Yes           | standalone        | clone source
git worktree          | N/A          | N/A           | shared            | N/A

註記:
* git clone 如果是接 path to local repository 的話, 則預設會開啟 `--local`, 
* `git clone --local` 時, `.git/objects/` 的檔案下會使用 hardlink 方式節省空間, 如果有帶 `--no-hardlinks` 則會 copy 一份新的
* `--shared`, `--reference`, `--bare` 和 `--mirror` 都可以 clone local repository

## Difference between shared and reference

* `git clone --shared` 和 `git clone --local` 的差別只有在 object store 共用而已.
* `git clone --reference` 和 `git clone --shared` 會在 `.git/objects/info/alternates` 寫入 shared repository 的 `GIT_DIR/objects` 位址.
當因操作產生新的 object 時, object 會存放在新的 object store 中.
* `git clone --reference` 和 `git clone --shared` 不同之處在於, 前者 tracking remote repos, 後者 tracking local repos.
當 fetch remote 時, 前者會從 remote 抓最新的 objects 下來更新到 local, 後者要等被 cloned 的 repopsitory 更新才能拿到最新的 objects.
Push 時也是如此, 前者可以直接 push 到 remote, 後者要先 push 到 local 被 cloned 的 repository 再從該 repository push 到 remote.
* `git clone --reference` 需要同時帶 path to local repository 和 remote repository, clone 時會從 remote download 不存在於被 cloned repository 裡的 objects
* `git clone --reference --disassociate` 不會建立 alternates, git 會先抓一份 local 的 object store, 再從 remote fetch.
clone 完後兩者的 object store 是分開的.
* `git clone --reference` 和 `git clone --shared` 在查找 objects 時都需要看 `.git/objects/info/alternates` 的 object store.
如果此 object store 被 delete, 則此 repository 也就會 corrupt.
若要把 shared 的關係斷開, 則可以
```shell
git repack -a
echo "" > .git/objects/info/alternates
```
* 如果不小心誤刪 shared 的 object store 或是改動 branch, 都會影響到另一個 repository, 所以後來才會開發出 `git worktree`.

## Difference between bare and mirror

Option  | Working Dir | core.bare | Branches | Tags             | Clone Source | Copy on Clone | Object Store |
-----------------------------------------------------------------------
default | Yes         | false     | Yes           | standalone   |
bare    | No          | true      | Yes           | standalone   |
mirror  | Yes         | true      | Yes           | standalone   |
