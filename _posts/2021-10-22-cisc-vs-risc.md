# Difference

* CISC is favoring hardware-level complexity (complex hardware logic to execute an instruction) and RISC favors software level complexity (complexed compiler to compile code into simple instructions).
* RISC needs more cache and registers because:
  * code is compiled to more simple instructions
  * all instructions have the same size, except ARM's Thumb instruction set, which consists of 16-bit instructions that act as a compact shorthand for a subset of the standard 32-bit instructions.
  * no instruction can directly do arithmetic operations on memory, data should be read from memory to register first, then write back after arithmetic operations

# CISC

The complex instruction sets appeared because of the high cost of memory as well as the difficulty of producing good compilers. 

[Micro-operation](https://en.wikipedia.org/wiki/Micro-operation)
* allows machine instructions be decomposed to micro-operations, so that the execution cycle of each instruction/micro-ops are nearly equaled and improves the performance of pipeline.
* cannot be generated by a compiler

[Microcode](https://en.wikipedia.org/wiki/Microcode)
* a layer of hardware-level instructions that implement higher-level machine code instructions or internal state machine sequencing in many digital processing elements.
* implementing complex instructions as being made up of small programs themselves
* hard to debug since they are in CPU ROM, not memory.

# Superscalar vs. Pipeline

* Both are techniques for implementing instruction-level parallelism within a single processor.
* Both pipeline and superscalar are implemented within a single proecessor.

* Pipelining exploits parallelism in the "stages" of instruction execution.
* Superscalar exploits parallelism of independent instructions --> instruction level parallelism (ILP) and out-of-order execution
  * execute more than one instruction during a clock cycle by simultaneously dispatching multiple instructions to different execution units on the processor.
  * CPU dynamically checks for data dependencies between instructions at run time (for OoO execution)
  * All general-purpose CPUs developed since about 1998 are superscalar.

## Pipeline

[Instruction pipelining](https://en.wikipedia.org/wiki/Instruction_pipelining) attempts to keep every part of the processor busy with some instruction by dividing incoming instructions into a series of sequential steps (the eponymous "pipeline") performed by different processor units with different parts of instructions processed in parallel. 

## Superscalar

A superscalar CPU is typically also pipelined.

The complexity and time cost of dependency checking logic and register renaming circuitry limit the performance improvemnet of superscalar CPUs.
Some architectural changes are proposed to counter this:
* Very long instruction word (VLIW) delegate the dependency checking by hardware logic at run time to the compiler.
* Explicitly parallel instruction computing (EPIC) is like VLIW with extra cache prefetching instructions.
* Simultaneous multithreading (SMT) permits multiple independent threads of execution to better utilize the resources provided by modern processor architectures.

A multicore CPU is possible where each core is an independent processor containing multiple parallel pipelines, each pipeline being superscalar. Some processors also include vector capability.

A superscalar processor dispatches multiple instructions from a [instruction window](https://en.wikipedia.org/wiki/Instruction_window) to different execution unit.

[Shelving buffer](https://en.wikipedia.org/wiki/Shelving_buffer) is a technique used in computer processors to increase the efficiency of superscalar processors.
  * It allows for multiple instructions to be dispatched at once regardless of the data dependencies between those instructions, so that OoOE can occur
  * Withour shelving buffer, if instruction 1 and instruction 2 has data dependency, the processpor is not allowed to dispatch instruction 2 and its following instructions until instruction 1 is completed
  * With shelving buffer, the superscalar CPU can bypass instruction 2, and dispatch instruction 1 and instruction 3 (if no data dependency) simultaneously.

# Simultaneous Multithreading vs. Superscalar

Simultaneous multithreading (SMT) improves the overall efficiency of superscalar CPUs with hardware multithreading by permitting multiple independent threads of execution to better use the resources provided by modern processor architectures.
* Instructions from more than one thread can be executed in any given pipeline stage at a time.
* Issue multiple instructions from multiple threads in one cycle.
* That means more than one tasks (from Linux perspective) are executed at the same time --> which means from kernel view, there are more than one processors.

Superscalar technique tries to exploit instruction level parallelism (ILP), and SMT exploits thread level parallelism (TLP).
Superscalar executes multiple instructions at the same time, but these instructions are dipatched from the same instruction stream.
SMT execute instructions from different instruction streams at the same times.
Both techniques leverage spare execution units to realize parallelism.

Inte;'s hyper-threaded is an implementation of SMT.

Temporal multithreading can only execute one thread at a time, but issue instructions from different threads interleavingly.
* Fine-grained multithreading issues instructions for different threads after every cycle
* Coarse-grained multithreading only switches to issue instructions from another thread when the current executing thread causes some long latency events (like page fault etc.)
* Can also be combimed with superscalar

# Macroarchitecture vs. Microarchitecture

[Microarchitecture](https://en.wikipedia.org/wiki/Microarchitecture), also called computer organization, is the way a given instruction set architecture (ISA) is implemented in a particular processor.
[Computer architecture](https://en.wikipedia.org/wiki/Computer_architecture) is the combination of microarchitecture and instruction set architecture.


Macroarchitecture is the area of a processor die that's taken up by all of the blocks that are not a processor core (which is about microarchitecture)
Macroarchitecture includes I/O interfaces, caches, buses, various accelerators, etc.
As core counts rise, the GPU moves on-die, and SoCs become a more prevalent part of mainstream (non-embedded) computing, macroarchitectural issues will increasingly come to define performance on the hardware side, much more so than microarchitectural issues.

ISA is roughly the same as the programming model of a processor as seen by an assembly language programmer or compiler writer.
ISA includes the instructions, execution model, processor registers, address and data formats among other things.

# Data Dependency and Hazards

All above acceleration methods will affect data dependency.
Recklessly executing multiple instructions without considering related dependences may cause danger of getting wrong results, namely [hazards](https://en.wikipedia.org/wiki/Hazard_(computer_architecture)).
